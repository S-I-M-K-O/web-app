[+] Short summary:


HERMES is a voice-activated AI chatbot that lives in your web browser. Say the wake word, ask your question, and it thinks and answers aloud. Everything runs in a single Docker container: a Go backend, a local Ollama model, and a Piper text-to-speech voice. No API keys, nothing leaves the machine.


[+] Problem:


The big cloud voice assistants are convenient, but your speech and context get sent to somebody else's servers. For a DevSecOps mindset that's a non-starter. I wanted a voice assistant that is fully local - wake word, speech recognition, LLM and text-to-speech all running on my own hardware.


[+] Solution:


HERMES - built in Go, containerized with Docker Compose, and reachable at http://localhost:8080. This is the stack:

┬

├─ Go backend - chat proxy, local knowledge base, Piper TTS, settings API

├─ Ollama - local LLM (qwen3.5), nothing leaves the machine

├─ Piper TTS - local voice model (BT7274) bundled in the container

├─ Web UI - chat frontend + animated visor eye with reactive states

├─ Wake word - "Hermes" via browser speech recognition

└─ Docker compose - one container, docker compose up -d --build


The animated visor eye in the center of the page reflects the state: idle drift, awaiting your call, scanning while the answer streams, pulsing while it speaks, and jittering when something fails. It pauses listening while talking, so it never hears itself.


[+] Lessons learned:


The backend first checks a small built-in knowledge base for greetings and common phrases; only if there's no local match does it call the local Ollama model and stream the response. That keeps instant answers offline and snappy. Reaching the host Ollama from inside the container via host.docker.internal was the one gotcha worth remembering.

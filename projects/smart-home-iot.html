[+] Short summary:


A self-built IoT system for the home. Sensors, actuators and automations fully under my control - local-first, no vendor cloud accounts, no guessing what happens to my data.


[+] Problem:


Most smart home gadgets only work through their vendor app and their cloud. If the vendor dies or the internet is down, a "smart" light becomes a dumb light. And all the data about my daily life flows through third-party services.


[+] Solution:


The whole system runs on local hardware with standard protocols. Components:

┬

├─ Home Assistant - central automation engine

├─ Mosquitto MQTT - message broker for all devices

├─ ESP32 nodes - sensor boards (temp, humidity, presence)

├─ Zigbee2MQTT - bridge for Zigbee sensors and switches

├─ Node-RED - automation flows

└─ Grafana + Influx - time-series data and dashboards


Everything is containerized on a small server in the rack and YAML-defined, so the whole config lives in git. A broken thing just gets restored from git instead of being clicked back together.


[+] Lessons learned:


MQTT as the single message bus pays off. Adding a new device is just a topic and a node - no vendor lock-in. The biggest gotcha was Zigbee interference with WiFi (2.4 GHz), solved by splitting the channels.

Hardware-side: ESP32 boards are cheap and reliable enough for a hobby setup. Blackouts can awake them in a weird state, so every node re-registers itself on boot instead of assuming a stable world.

[+] Short summary:


A private, self-hosted AI stack for the home lab. All inference runs on own hardware, no data leaves the house, and the whole thing is reachable from anywhere through a WireGuard tunnel.


[+] Problem:


Using the big cloud AI services is easy, but you pay with your data and a monthly subscription. Prompts and context go to somebody else's servers, get stored, and get used for training. For a DevSecOps guy that's like leaving your SSH key in a public gist - it works, but it feels wrong.

I wanted an assistant that I can also feed home automation data and personal context into, without any third party being able to read along.


[+] Solution:


Self-hosting on a small GPU node (NVIDIA RTX, ~8 GB VRAM) in the rack. This is what the stack looks like:

┬

├─ ollama - local model runtime

├─ open-webui - chat UI with user management

├─ llama.cpp - low-level inference backend

├─ Tailscale - zero-config WireGuard for remote access

├─ sematext / loki server - prompt + system logging

└─ docker compose - everything wrapped in containers


Every container sits behind a reverse proxy, and ssh-style key auth + SSRF hardening are in place so the web UI can never be abused as a proxy into the lab.


[+] Lessons learned:


The model matters more than the coolest UI. A quantized 7B parameter model runs fine on this hardware and covers 90% of the use cases like summarization and home automation callouts. Running the same model on CPU is technically possible but painfully slow.

What I would build differently next time: a proper RAG pipeline on top, so the assistant can actually query the smart home state instead of just chatting.
